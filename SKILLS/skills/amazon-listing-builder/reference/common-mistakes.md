# 五大常見誤區

> 演算法時代，Listing 最佳化不能再靠玄學。

---

## 誤區 1：把 Cosmo / Alexa 講成玄學

### 表現
很多賣家一聽新演算法，就開始找：
- "隱藏規則"
- "特殊寫法"
- "神秘關鍵詞"
- "Alexa 評分公式"

### 真相
**沒有必要**。無論演算法怎麼變，它最終都圍繞一個問題：
> 給使用者展示**最相關、最有可能成交、體驗最好**的商品。

### 正確做法
不要迎合玄學，讓 Listing：
1. 更相關
2. 更清楚
3. 更可信
4. 更能轉化

---

## 誤區 2：認為關鍵詞不重要

### 表現
聽到"COSMO 語義演算法"，就以為關鍵詞時代結束了，開始寫"自然語言文案"。

### 真相
**關鍵詞仍然是 Listing 的地基**。

| 沒有核心詞 | 系統不知道你屬於哪個市場 |
|----------|------------------------|
| 沒有屬性詞 | 系統不知道你的差異化 |
| 沒有場景詞 | 系統不知道你適合什麼用途 |
| 沒有問題詞 | 錯過對話式搜尋和 QA 內容機會 |

### 區別
關鍵詞不能再亂堆，**要分層組織**。

---

## 誤區 3：只最佳化標題

### 表現
"我把標題改了，應該會漲流量吧？" → 結果流量漲了，轉化沒漲。

### 真相
**Listing 是一個整體**。

| 模組 | 作用 |
|------|------|
| 標題 | 解決相關性和點選 |
| 主圖 | 解決第一眼理解 |
| 五點 | 解決購買理由 |
| 描述 + A+ | 解決場景和信任 |
| ST | 解決後臺補充索引 |
| QA | 解決疑慮 |
| 評論 | 驗證真實體驗 |

### 正確做法
所有模組協同最佳化，不要只改標題。

---

## 誤區 4：讓 AI 直接寫一版 Listing 就上線

### 表現
"用 ChatGPT / Codex 幫我寫一個標題和五點" → 直接複製貼上上線。

### 真相
**AI 很會寫，但如果沒有資料，它會寫出漂亮廢話**。

| AI 寫出來的空話 | 應該寫的 |
|--------------|--------|
| premium quality | 寫具體材料（PE plastic / stainless steel） |
| perfect for any occasion | 寫具體 2-3 個場景 |
| easy to use | 寫具體怎麼用 |
| great gift | 寫適合什麼人送禮 |
| 100% no fade | help reduce fading |

### 正確做法
**先讓 AI 建庫，再讓它寫草稿，最後由人稽核**：

```
準備階段：
1. 詞庫（分層）
2. 痛點庫（來自評論）
3. 問題庫（來自 QA / 客服）
4. 證據庫（材料/工藝/資料）

生成階段：
5. 多版本草稿（至少 3 版標題）

校驗階段：
6. 合規檢查
7. 語義覆蓋檢查
8. 轉化邏輯檢查
```

---

## 誤區 5：用一個 Listing 承接所有人群

### 表現
"我的產品可以用於庭院、門廊、陽臺、墓地、婚禮、辦公室、home、學校、餐廳...全部塞標題！"

### 真相
**一個產品可能有多個場景，但 Listing 必須有主場景**。

戶外模擬植物可以用於：
- 庭院 ✅
- 門廊 ✅
- 陽臺 ✅
- 墓地（次場景）
- 婚禮（次場景）
- 辦公室（第三層）

但**主圖和標題不可能同時講透所有場景**。

### 正確做法
1. 確定主詞 + 主場景（來自詞庫 P0 關鍵詞）
2. 主圖、標題、五點 1-3 都圍繞主場景
3. 其他場景放到五點 4-5、A+、QA 承接
4. ST 補充次場景詞索引

## 自檢清單

每次做 Listing 前問自己：

- [ ] 我是否在找"隱藏規則"？（誤區 1）
- [ ] 我是否忽略了關鍵詞分層？（誤區 2）
- [ ] 我是否只改了標題？（誤區 3）
- [ ] 我是否讓 AI 直接寫了一版？（誤區 4）
- [ ] 我是否試圖把所有人群塞進一個 Listing？（誤區 5）

如果任何一項是 ✅，回到本指南相應章節重新理解。

---

## 一句話總結

> **Listing 不是文案工作，而是流量效率工程。**

- 一點轉化率差距 → 利潤放大成倍差距
- CPC 同樣 $0.8，5% CVR vs 10% CVR → 獲客成本翻倍
- 演算法用 CTR/CVR/退貨/評論/銷量判斷誰更值得展示
- 所以 Listing 是**系統工程**，不是寫幾句文案
