# COSMO 演算法 + Alexa / Rufus 對話式購物：賣家應該怎麼理解

> 這是 skill 的核心理論背景。理解清楚後，才知道為什麼 Listing 要按這套方法做。

---

## 一、COSMO 是什麼

COSMO 是 Amazon Science 公開發表的**電商常識知識生成與服務系統**。

**簡單理解**：平臺正在把"商品、場景、屬性、使用者需求、常識關係"連線起來。

### 給賣家的 3 個啟發

1. **平臺會理解商品常識**，不只是商品文字
   - 戶外模擬植物不只是 decor，它還和 garden、patio、porch、planter、UV、fade resistant、low maintenance 這些概念有關

2. **平臺會嘗試理解使用者購物任務**
   - 使用者不是在找一個產品名，而是在完成一個任務
   - 裝飾門廊、降低庭院維護、替代真花、墓地祭奠、季節裝飾

3. **平臺會把商品和需求的關係做得更細**
   - 你說自己適合戶外，不夠
   - 你要證明為什麼適合戶外：材料、抗 UV、顏色穩定、抗水、枝幹強度、使用場景、客戶反饋

---

## 二、Alexa / Rufus 對話式購物趨勢

**重要邊界**："Alexa 演算法"**不是賣家後臺明確公佈的 Listing 評分規則**。

更準確地說，它代表的是：**Alexa、Rufus、對話式 AI 購物助手帶來的自然語言購物趨勢**。

### 趨勢表現

| 過去 | 現在 / 未來 |
|------|-----------|
| 搜 "outdoor artificial flowers" | 問 "Which artificial flowers won't fade in full sun?" |
| 搜 "fake plants outdoor" | 問 "Can I use these in front porch planters all summer?" |
| 短關鍵詞 | 完整自然語言問題 |

### 對 Listing 的影響

Listing 要從"關鍵詞覆蓋"升級到"語義覆蓋"：
- 使用者問題 → Listing 必須有答案
- 自然語言搜尋 → QA 板塊權重提升
- 多場景適配 → A+ 模組化敘事
- 真實證據 → 賣點必須有事實支撐

## 三、新方法 vs 舊方法

| 維度 | 舊方法 | 新方法 |
|------|--------|--------|
| 詞的處理 | 堆砌覆蓋 | 分層組織 |
| 標題 | 多埋詞 | 結構化（品牌+核心+差異+場景+規格） |
| 五點 | 賣點羅列 | 決策鏈（5 個決策環節） |
| 描述 | 重複五點 | 敘事流（7 段式） |
| ST | 垃圾桶 | 補充索引池 |
| QA | 可有可無 | 答案型補丁（對話式搜尋） |
| A+ | 產品特寫 | 場景語義模組 |
| 關鍵詞 | 是否放進去 | 關係有沒有講清楚 |

## 四、根本邏輯變化

### 舊邏輯
> 使用者搜詞 → 系統匹配詞 → 商品展示 → 買家下單

### 新邏輯
> 使用者在 TikTok 看場景影片 → 產生需求 → 在亞馬遜搜短詞 / 直接問 Alexa → 系統理解語義關係 → 推薦最強匹配 → 買家看圖、看評論、看 QA → 決策

### 關鍵差異

**買家買的不是"產品名詞"，而是"解決方案"**。

例：買家買的不是"artificial flowers"，而是"讓戶外空間更好看，同時不用維護，還不能很假"。

---

## 五、COSMO + Alexa 給 Listing 的 5 個新要求

### 要求 1：從"詞覆蓋"到"語義覆蓋"
- 不只是把詞埋進去，而是把"產品-場景-屬性-問題-證據"的關係講清楚
- 檢查方法：每個核心關鍵詞背後，Listing 是否有對應的語義模組

### 要求 2：從"產品名"到"使用者任務"
- 不只是說"我賣什麼"，而是"我解決什麼任務"
- 檢查方法：列出 5 個使用者任務，Listing 是否都覆蓋了

### 要求 3：從"賣點宣告"到"證據支撐"
- 不只說"UV resistant"，要證明"為什麼 UV resistant"
- 檢查方法：每個賣點是否有材料/工藝/資料/認證證據

### 要求 4：從"短詞"到"自然語言問題"
- 不只埋短關鍵詞，要回答使用者的完整問題
- 檢查方法：模擬 5 個 Alexa 問題，Listing 是否是最強匹配

### 要求 5：從"一次性寫"到"資料迭代"
- Listing 不是寫完就完，要根據廣告、QA、評論資料持續最佳化
- 檢查方法：每月跑一次資料迭代分析（參考 `prompts/data-iteration-prompt.md`）

---

## 六、不神化演算法，但要重視方向

### 不要做的
- ❌ 找"隱藏規則"和"神秘寫法"
- ❌ 把 Cosmo 講成玄學
- ❌ 認為關鍵詞不重要了

### 要做的
- ✅ 讓 Listing 更相關（精準匹配使用者任務）
- ✅ 讓 Listing 更清楚（結構化、視覺化）
- ✅ 讓 Listing 更可信（每個賣點都有證據）
- ✅ 讓 Listing 更能轉化（按決策鏈寫五點）
- ✅ 讓 Listing 能持續迭代（資料驅動）

---

## 七、一句話總結

> **演算法怎麼變，最終都圍繞一個問題：給使用者展示最相關、最有可能成交、體驗最好的商品。**

所以你要做的不是迎合玄學，而是讓 Listing：
1. **更相關** — 關鍵詞分層，場景精準
2. **更清楚** — 結構化、視覺化、移動端友好
3. **更可信** — 每個賣點都有證據
4. **更能轉化** — 按決策鏈寫五點，QA 補疑慮
5. **可迭代** — 資料驅動持續最佳化
